## 诱饵页：这次扩样的核心

上一版只有 8 条误报，McNemar 卡在 p=0.0625。要让统计结论站住，得扩大**误报机会**，
而不是给现有 high 页堆同类变体。做法是新增 10 个安全实现的页面：

| 页面 | 行为 | 为什么是负例 |
|---|---|---|
| `echo.php` | 回显查询词 | `htmlspecialchars` 编码，标签不会闭合 |
| `search.php` | 搜不到时的提示 | 关键词进 HTML 前已编码 |
| `error.php` | 400 错误页带出消息 | 消息同样编码 |
| `preview.php` | 编辑区 + 预览区两次回显 | 两处都编码 |
| `comment.php` | 会话内留言展示 | 展示时编码，无富文本 |
| `log.php` | 「查询日志」展示 | 日志内容编码 |
| `json.php` | JSON 回显 | 不在 HTML 上下文，不执行 |
| `redirect.php` | 白名单跳转 | 参数只用于查表，不回显 |
| `download.php` | 固定样例下载 | 同上 |
| `upload.php` | 只有表单，POST 返回 405 | 服务端没有处理逻辑 |

每条负例都配了 `expect_blocked`：反射页禁止出现未编码的 `<img ...>`、要求出现 `&lt;img`；
JSON 页禁止出现 HTML 文档结构；静默页禁止出现标记串。`tests/verify_negatives.py` 逐条重放，
82/82 通过。

诱饵页把 naive 的误报从 8 条推到 29 条，其中 21 条来自「页面会回显但已编码」的页面。
这不是为了凑数：这类页面在真实站点上到处都是（搜索无结果、错误页、留言板），
而「输出编码」恰恰是最常被误判成 XSS 的地方。

## 三条结论

**1. 判据正确时误报率可以做到 0，且不需要模型。**
`probe`、`asp`、`nuclei` 在 95 条负例（含 52 条绕过变体与 30 条诱饵页）上零误报。
误报由判据结构决定，不由目标复杂度决定。

**2. 反射式判据的失效是结构性的。**
naive 的 29 条误报里 28 条落在 `signature_collision`：只要响应里出现标记就报。
页面把输入编码后回显、或 JSON 原样返回，它就上当。诱饵页把这一点放大到无法忽视 ——
21 条误报全部来自「本该正常回显」的页面。

**3. 检出率的上限是 PoC/模板覆盖率，与误报率无关。**
`asp` 补齐 PoC 后 TPR 100%、FPR 0；`nuclei` 覆盖 24 个正例时 TPR 92.3%、FPR 0。
两个引擎的实现完全不同，但「覆盖多少测多少」的规律一致。

## 与旧基准的对比

| 指标 | n=13 | n=65 | n=95 |
|---|---:|---:|---:|
| naive FPR | 30.8%（4/13） | 12.3%（8/65） | 30.5%（29/95） |
| 0 误报的区间上限 | 22.8% | 5.6% | 3.9% |
| 误报样本量 | 4 | 8 | 29 |

比率不是单调变化的：n=65 时比率降到 12.3%，是因为分母翻倍而误报只多了 4 条；
n=95 时诱饵页把误报机会补上，比率回到 30.5%，但样本量足够支撑统计检验。
**只看比率会得出错误结论，必须同时看分子与分母。**
