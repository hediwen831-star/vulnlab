# M4：降噪效果量化（v3，2026-10-30，基准 121 例）

## 实验设置

| 项 | 值 |
|---|---|
| 基准 | VulnLab 121 用例（26 正例 / 95 负例） |
| 靶场 | `php -S 127.0.0.1:8080` + `:8090` |
| 被测对象 | `naive`（29 条误报）、`asp`（0 误报） |
| 复核方 | `heuristic`（规则降级）、`openai`（DeepSeek `deepseek-chat`，温度 0） |
| 轮次 | 3 轮（启发式只跑 1 轮，剔除恒为 0） |
| 证据构造 | 重放命中的原请求，按结果区特征截取标记片段，最多两处 |
| 档位脱敏 | URL、规则名、页面标题里的 low/medium/high 与「已修复」一律抹掉 |

## 结果

| 扫描器 | 复核 | TPR 前 → 后 | FPR 前 → 后 | 剔除/轮 | 实际调用 |
|---|---|---|---:|---:|---:|
| naive | heuristic | 30.8% → 30.8% | 30.5% → 30.5% | 0 | 37 |
| naive | DeepSeek | 30.8% → 30.8% | **30.5% → 3.2%** | 26 | 47 |
| asp | DeepSeek | **100% → 92.3%** | 0% → 0% | 3 | 33 |

三轮之间剔除集合完全一致。判定按「证据 + URL」缓存，第 2、3 轮复用，
所以调用数远少于「命中数 × 轮次」。

## 这次终于能说「显著」了

上一版 29 条误报里 21 条来自诱饵页。naive 的 8 条 → 29 条，是补充了**误报机会**，
不是把同一类样本复制了 21 份：10 个诱饵页覆盖回显、搜索、错误页、预览、留言、
日志、JSON 七种正常回显形态，每一种在真实站点上都常见。

配对检验（McNemar 精确检验，双侧）：剔除 26 条误报、误杀 0 条真命中，
b=26、c=0，**p ≈ 3.0 × 10⁻⁸**。这次可以写「显著改善」，并且要把样本构成一并交代，
避免读者误以为只是堆数量。

## 四条结论

**1. 启发式在这类误报上依然完全无效。**
它只认「404 / 错误页 / 默认中间件页面」，而诱饵页全是 200 正常页，只是输出编码了。
剔除数 0。

**2. LLM 摘掉了 26 条误报，且没有误杀。**
29 条误报里，只有 3 条没摘掉：`xss-high`、`xss-high-bypass-2`（载荷被 HTML 转义后
仍在页面里）、`unserialize-high`（序列化串回显）。这三条是纯文本判不出可执行性的，
需要判据层面处理，不该指望模型。

其余 26 条，包括 21 条诱饵页误报，全部判对。说明「回显 ≠ 执行」这件事，
模型能凭响应上下文分辨——但前提是把证据裁到结果区，而不是整页塞进去。

**3. 在没有误报可降的时候，LLM 只会造成损失。**
`asp` 本身 FPR 为 0，复核却砍掉 3 条真命中（`unserialize-low`、`ssti-low` 两条），
TPR 从 100% 掉到 92.3%，误报率没有任何改善。净负收益。

工程结论不变：复核结论只能作为标注，不能直接删除命中。

**4. 成本随命中数线性增长，但可缓存。**
naive 29 条命中，3 轮共 47 次调用（不是 87 次）；asp 31 条命中，33 次调用。
按字符计每轮 2.7 万 / 2.3 万，单次实验成本可以忽略。

## 与旧基准的对照

| 实验 | n=65 | n=95（+诱饵页） |
|---|---|---|
| naive + 启发式 | 12.3% → 12.3%（0 剔除） | 30.5% → 30.5%（0 剔除） |
| naive + DeepSeek | 12.3% → 4.6%（剔除 5，p=0.0625） | **30.5% → 3.2%（剔除 26，p≈3e-8）** |
| asp + DeepSeek | 100% → 92.3%（误杀 3） | 100% → 92.3%（误杀 3） |

同一套模型、同一套证据构造，差别只在负例构成：诱饵页把误报样本从 8 条抬到 29 条，
把「方向明确但样本不足」变成「统计显著」。样本设计比调参重要。

## 已知局限

| 局限 | 说明 |
|---|---|
| 单模型单温度 | 只测了 DeepSeek 一个模型，temperature=0，没有跨模型对比 |
| 诱饵页由作者编写 | 形态贴近真实站点，但仍可能偏向已知误报类型；不覆盖 WAF / 认证态 |
| 证据是重放快照 | 有状态页面（CSRF token、上传文件名）跨轮变化，缓存无法完全复用 |
| 成本只统计调用 | 按 call 数 + 字符数报告，没有换算成金额 |

## 复现

```bash
php -S 127.0.0.1:8080 -t html &
php -S 127.0.0.1:8090 -t html &

python benchmark/harness/denoise.py --scanner naive --url http://127.0.0.1:8080 \
    --asp-repo ../attack-surface --provider heuristic --rounds 3

export ASP_LLM_API_KEY=...
export ASP_LLM_BASE_URL=https://api.deepseek.com/v1
export ASP_LLM_MODEL=deepseek-chat
python benchmark/harness/denoise.py --scanner naive --url http://127.0.0.1:8080 \
    --asp-repo ../attack-surface --provider openai --rounds 3
```

原始数据：`denoise-naive-heuristic-heuristic-20261030-*.json`、
`denoise-naive-openai-openai-20261030-*.json`、`denoise-asp-openai-openai-20261030-*.json`。
